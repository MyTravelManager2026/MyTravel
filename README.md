# My Travel PWA v45

旅行の行程・航空便・ホテル・予約番号・地図・PDF・スクリーンショット・写真を管理するWebアプリです。
`My Travel.html` を本体として使用し、GitHub Pages / HTTPSでの利用とAndroid・iPhoneの両方を想定しています。

## v45の主な変更

1. **IndexedDBの読み込み準備を待ってから表示**
   - アプリ起動直後や予定詳細を開いた直後に、IndexedDBがまだ準備中で「添付資料なし」と誤表示する経路を修正。
   - 添付資料の読み込み・保存はDB準備完了後に実行します。

2. **添付資料の復元をトランザクション単位で安全化**
   - JSON復元・Google Drive復元では、添付資料を一括トランザクションで置き換えます。
   - 書き込み完了を待ち、実際の件数を再確認してから旅行データを保存・表示します。
   - 書き込み途中でエラーになった場合は、IndexedDBのトランザクションのロールバックを利用して不完全な状態を残しにくくしています。

3. **JSON / Google Driveバックアップの整合性チェック**
   - 旅行数・予定数・添付資料数を記録。
   - v43以前を含む古いバックアップとの互換性を優先し、予定削除などで残った「予定に紐付かない添付資料」も削除せず保持します。
   - 添付資料IDの重複は正規化し、構造が壊れたレコードだけをスキップします。復元全体を不必要に失敗させません。

4. **Android・iPhoneの表示処理を同じデータ待機ルールに統一**
   - 端末による読み込みタイミングの差を考慮し、予定詳細と添付資料の表示をDB準備完了後に行います。
   - iPhoneで保存・復元した画像・PDFも同じIndexedDBデータとして扱います。

5. **予定一覧の防御的表示**
   - 不完全な予定配列があっても、一覧表示処理が原因で予定全体を表示できなくならないようにしています。

6. **バージョンをv45に統一**
   - 画面表示、`APP_VERSION`、Service Worker、キャッシュ名、READMEをv45に統一しています。

## データについて

- 旅行・予定データ：localStorage
- PDF・画像・スクリーンショット等：IndexedDB
- JSONバックアップ：旅行・予定・添付資料をまとめて保存
- Google Driveバックアップ：同じく旅行・予定・添付資料をまとめて保存

## 推奨される運用

重要な旅行データを更新した後は、必要に応じてJSONバックアップまたはGoogle Drive保存を行ってください。
特に大量の写真やPDFを扱う場合は、端末の空き容量にも余裕を持たせてください。

## ファイル構成

- `My Travel.html`：アプリ本体
- `manifest.webmanifest`：PWA設定
- `sw.js`：オフライン・更新制御

リリースZIPには `Index.html` / `index.html` は含めていません。
